---
title: A practical software project brief
description: Prepare for a useful first conversation with your software partner.
sections:
  - title: Start with the problem
    text: >-
      Describe the workflow or customer problem in plain language. Who encounters it, how do they handle it
      today, and what does that cost in time or effort? Separate the problem from a preferred technical
      solution.
  - title: Define a useful first release
    text: >-
      List the smallest set of capabilities that would make a real difference. Identify what must work on day
      one and what can follow. Include the people who will decide whether the release is acceptable.
  - title: Map the constraints
    text: >-
      Document existing systems, integration owners, data availability, hosting requirements and accessibility
      needs. Identify any contractual or regulatory requirements for specialist review. Never share production
      credentials in the brief.
  - title: Agree on success
    text: >-
      Choose a few observable outcomes: fewer manual steps, better task completion, or a workflow that users
      can finish reliably. Record the current baseline where possible. An outcome is more useful than a long
      feature list.
  - title: Bring the right context
    text: >-
      Prepare sample workflows, anonymized data, existing designs and known deadlines. State the budget range
      and explain any deadline dependencies. Agree who can provide timely feedback and who owns final
      decisions.
